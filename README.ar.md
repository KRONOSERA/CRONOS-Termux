# CRONOS — دليل التثبيت والتشغيل بالعربية

**الإصدار الموثّق: 3.0.1 — نسخة قيد التحقق**  
**المستودع:** [KRONOSERA/CRONOS-Termux](https://github.com/KRONOSERA/CRONOS-Termux)  
[English / project overview](README.md) · [سجل التغييرات](CHANGELOG.md) · [حالة الأمان](SECURITY.md)

CRONOS أداة مفتوحة المصدر تعمل داخل Termux على أندرويد لتنزيل الفيديو والصوت من YouTube وYouTube Music. تستخدم Python وyt-dlp وFFmpeg، وتقدّم واجهة طرفية تفاعلية، وإعدادات للدقة والصوت، وقوائم تشغيل، وطابور تنزيلات، وسجلًا ومكتبة محلية. لا تحتاج إلى روت أو خادم خاص.

> **اقرأ حالة التثبيت أولًا:** ملف `requirements.lock` المنشور مع 3.0.1 غير مكتمل عمدًا. التثبيت الجديد وتحديث المحرك المقفل يتوقفان حاليًا حتى يتوفر ملف اعتماديات صالح تمت مراجعته. يمكن محاولة ترقية شيفرة تثبيت 3.0.0 يعمل بالفعل باستخدام اعتمادياته الموجودة، ثم إجراء فحوص الجهاز. هذا الدليل يصف السلوك الموجود في الشيفرة؛ لا يعلن نجاح اختبار فعلي على جميع الهواتف.

## 1. اختر المسار المناسب

| حالتك | ما الذي تفعله؟ |
|---|---|
| لم تثبّت CRONOS من قبل | جهّز Termux واحصل على المصدر، ثم اقرأ قسم التثبيت الجديد. نسخة 3.0.1 الحالية لا تتجاوز ملف الاعتماديات غير المكتمل. |
| لديك CRONOS 3.0.0 يعمل في Termux نفسه | اتبع قسم الترقية؛ سيحاول المثبّت إعادة استخدام بيئة Python الموجودة. |

| لديك GloriousCronos أو CronosFetch أو تطبيق Seal | هذه مشاريع مختلفة؛ تعليمات الترقية هنا تخص حزمة `cronos-yt` ذات الأمر `cronos`. |
| لديك تثبيت يعمل وتريد تحديث الشيفرة فقط | اتبع تحديث المصدر من GitHub ثم شغّل المثبّت. أمر `cronos --update` يحدّث المحرك والاعتماديات، وليس شيفرة CRONOS. |

<a name="requirements"></a>
## 2. المتطلبات وتثبيت Termux

| المتطلب | التفاصيل |
|---|---|
| النظام | أندرويد مع بيئة Termux الأصلية؛ المثبّت يرفض التشغيل خارجها. هذا ليس APK مستقلًا. |
| Python | الإصدار 3.12 أو أحدث بحسب `pyproject.toml`. |
| Node.js | الإصدار 22 أو أحدث بحسب فاحص الاعتماديات داخل المشروع. |
| FFmpeg وFFprobe | لدمج الفيديو والصوت والتحويل وفحص الوسائط؛ توفرهما حزمة `ffmpeg` في Termux. |
| حزم Python | yt-dlp وyt-dlp-ejs وRich وQuestionary وMutagen والاعتماديات المتعدية. وجود Python وحده لا يكفي. |
| الاتصال | مطلوب لتنزيل حزم النظام والاعتماديات والوسائط. التشغيل محلي ولا يحتاج إلى خادم مدفوع. |
| التخزين | مساحة للملف النهائي ولأجزاء التنزيل والدمج والتحويل المؤقتة. لا يوجد حجم ثابت يناسب كل فيديو. |
| الروت وTermux:API | الروت غير مطلوب. Termux:API اختياري لبعض وظائف الحافظة وفحص الوسائط. |

يمكن تنزيل Termux من [صفحته على F-Droid](https://f-droid.org/packages/com.termux/) أو من [إصدارات المشروع الرسمية](https://github.com/termux/termux-app/releases). راجع [تعليمات Termux الرسمية](https://github.com/termux/termux-app#installation) لاختيار نسخة متوافقة مع جهازك.

إذا أضفت Termux:API، فثبّت تطبيقه من **المصدر نفسه** الذي استخدمته لتطبيق Termux، لأن توقيعات التطبيقات والإضافات يجب أن تتوافق. لا تُزل Termux لتغيير مصدره قبل حفظ بياناتك؛ إزالة التطبيق تمسح بياناته الخاصة.

<a name="prepare"></a>
## 3. تجهيز الطرفية والتخزين

الأوامر التالية تُكتب **داخل Termux**. لا تنسخ علامة `$` أو اسم المستخدم الذي قد يظهر قبل الأمر في الصور. اضغط Enter بعد كل أمر، وانتظر انتهائه.

### تحديث فهرس الحزم وتثبيت Git

```bash
pkg update
pkg install git
```

`pkg update` يحدّث فهرس الحزم. أما `pkg upgrade` فيرقّي حزم Termux المثبتة كلها، وهو إجراء أوسع لا يحتاجه هذا الدليل تلقائيًا. المثبّت نفسه لا ينفّذ أيًّا منهما.

إذا ظهرت رسالة تؤكد تثبيت حزم، اقرأ الملخص ثم وافق عند رغبتك. إذا فشل أمر سابق، عالج الخطأ قبل الانتقال إلى الخطوة التالية.

### السماح بالوصول إلى التخزين المشترك

```bash
termux-setup-storage
```

امنح إذن التخزين في نافذة أندرويد عند ظهورها. يمكن فحص مجلد التنزيلات باستخدام:

```bash
ls "$HOME/storage/downloads"
```

احتفظ **بشيفرة المشروع وبيئة Python داخل مجلد Termux الخاص**، مثل `~/CRONOS-Termux`. اجعل ملفات الفيديو والصوت في التخزين المشترك. لا تثبّت البيئة الافتراضية داخل `/storage/emulated/0`.

<a name="source"></a>
## 4. الحصول على المشروع من GitHub

### الطريقة المفضلة للتحديثات اللاحقة: Git

إذا لم يكن لديك المجلد `~/CRONOS-Termux`:

```bash
git clone https://github.com/KRONOSERA/CRONOS-Termux.git "$HOME/CRONOS-Termux"
cd "$HOME/CRONOS-Termux"
git remote get-url origin
git status --short
```

ينبغي أن يشير `origin` إلى هذا المستودع، وأن يحتوي المجلد على `install.sh` و`pyproject.toml` ومجلد `cronos_yt`.

```bash
ls
```

**الاستنساخ ينسخ المصدر فقط.** لا يُثبّت التطبيق ولا ينشئ الأمر `cronos` بمفرده. إذا قال Git إن المجلد موجود مسبقًا، فلا تحذفه؛ افحص محتواه وانتقل إلى قسم تحديث المصدر إذا كان هو الاستنساخ الصحيح.

### بديل من الهاتف: ملف ZIP

1. افتح صفحة المستودع في المتصفح واختر **Code → Download ZIP**.
2. احفظ الملف في مجلد التنزيلات في أندرويد.
3. ثبّت أداة فك الضغط وافحص اسم الملف الفعلي:

```bash
pkg install unzip
ls "$HOME/storage/downloads"
```

إذا كان اسمه `CRONOS-Termux-main.zip`:

```bash
unzip -n "$HOME/storage/downloads/CRONOS-Termux-main.zip" -d "$HOME"
cd "$HOME/CRONOS-Termux-main"
```

الخيار `-n` يحافظ على الملفات الموجودة ولا يستبدلها. لذلك فكّ تحديث ZIP لاحقًا في **مجلد جديد** حتى لا تختلط نسختان. إذا تغيّر اسم ZIP أو مجلده الداخلي، استعمل الاسم الموجود فعلًا. أرشيف `CRONOS-v3.0.1.zip` القديم يحتوي على مجلد `CRONOS` بدلًا من `CRONOS-Termux-main`.

من ثبّت عبر ZIP لا يستطيع استعمال `git pull` داخل المجلد ما لم يكن مستودع Git حقيقيًا. استعمل ZIP جديدًا أو أنشئ الاستنساخ المفضّل أعلاه.

<a name="fresh"></a>
## 5. التثبيت الجديد: الحالة الحالية

في المصدر المنشور حاليًا، `requirements.lock` عبارة عن ملاحظة تفسيرية دون قائمة إصدارات وبصمات صالحة. لذلك **لا يوجد حاليًا مسار تثبيت جديد مكتمل للمستخدم النهائي بمجرد تشغيل أمر واحد**.

بعد الحصول على المصدر، قد يؤدي:

```bash
bash install.sh
```

إلى تثبيت بعض حزم Termux المطلوبة أولًا، ثم التوقف بالرسالة:

```text
ERROR: reviewed SHA-256 requirements.lock unavailable for fresh installation.
```

هذا توقف مقصود، ولا تعني الرسالة أن التنزيل من GitHub فشل. **قد تكون حزم النظام تغيّرت قبل التوقف**؛ لا يُوصف هذا الأمر بأنه فحص دون تغييرات.

المطلوب قبل إتاحة تثبيت جديد موثوق هو توليد ملف الاعتماديات ومراجعته وتدقيقه واختباره على Termux، ثم نشره مع المشروع. قسم المشرف أدناه يشرح ذلك. لا تُحوّل الملف إلى قائمة اعتماديات بلا بصمات، ولا تعتبر تثبيت أحدث حزم عشوائيًا بديلًا مكافئًا لهذا المسار.

عندما يعلن سجل التغييرات اكتمال ملف الاعتماديات واختبار الإصدار على جهاز متوافق، يكون مسار التثبيت من مجلد المصدر:

```bash
CRONOS_NO_LAUNCH=1 bash install.sh
```

المتغير `CRONOS_NO_LAUNCH=1` يمنع الفتح التلقائي بعد التثبيت فقط؛ لا يتجاوز فحص الاعتماديات أو إذن التخزين. لا تُعد تشغيل هذا الأمر الآن ضمانًا لنجاح التثبيت الجديد.

<a name="upgrade"></a>
## 6. ترقية تثبيت CRONOS 3.0.0 يعمل بالفعل

### أ. تحقق من التثبيت القديم

قبل الترقية، أنهِ التنزيلات وأغلق جلسات CRONOS الأخرى. نفّذ:

```bash
cronos --version
cronos --check
```

إذا كان اسم التشغيل القديم فقط متاحًا، استخدم `cronos-yt` في الأمرين. يفترض هذا المسار وجود Python قابل للتشغيل داخل:

```text
~/.local/share/cronos-yt/venv/bin/python
```

وجود مجلد فارغ بهذا الاسم أو بيئة مشروع مختلف لا يكفي. يمكن فحص البيئة الموجودة دون حذفها:

```bash
"$HOME/.local/share/cronos-yt/venv/bin/python" --version
"$HOME/.local/share/cronos-yt/venv/bin/python" -c "import yt_dlp, yt_dlp_ejs, rich, questionary, mutagen, cronos_yt; print(cronos_yt.__version__)"
```

إذا لم يعمل Python أو فشلت الاستيرادات، فهذه ليست بيئة سليمة يمكن ضمان إعادة استخدامها. احتفظ بها وراجع الأخطاء؛ قد يلزم ملف اعتماديات مكتمل لإعادة البناء، خصوصًا بعد تغيير إصدار Python في Termux.

### ب. احفظ نسخة احتياطية

إذا كان التطبيق القديم يعمل ويدعم الأمر:

```bash
cronos --backup
```

يحفظ الأمر الإعدادات وقاعدة بيانات السجل والطابور، **ولا ينسخ ملفات الفيديو والصوت**. احتفظ بنسخة منفصلة من الوسائط المهمة. ينشئ المثبّت أيضًا لقطة قبل تعديل بيئة التطبيق عندما يجد إعدادات أو قاعدة بيانات سابقة.

### ج. شغّل مثبّت المصدر الجديد

إذا استنسخت Git إلى المسار المفضّل:

```bash
CRONOS_NO_LAUNCH=1 bash "$HOME/CRONOS-Termux/install.sh"
```

إذا استخدمت ZIP، شغّل `bash install.sh` من المجلد الذي فككته فعلًا، مع `CRONOS_NO_LAUNCH=1` إن أردت منع الفتح التلقائي.

عند عدم وجود ملف اعتماديات صالح، يحاول المثبّت نسخ البيئة المثبتة وإضافة شيفرة CRONOS الجديدة دون ترقية اعتماديات Python. هذا **لا يضمن توافق كل بيئة قديمة**؛ لذلك يجب إجراء فحوص التشغيل بعده. كما أن أمر `pkg install` الخاص بحزم النظام قد يحتاج إلى الشبكة.

### د. تحقق ثم افتح التطبيق

```bash
cronos --version
cronos --check
cronos --doctor
cronos
```

ينبغي أن يعرض أمر الإصدار `CRONOS 3.0.1`. لا تكتفِ بوصول المثبّت إلى آخر سطر إذا أظهر تحذيرًا في فحص الاعتماديات.

<a name="installer"></a>
## 7. ما الذي يفعله المثبّت؟

| المرحلة | السلوك الموجود في `install.sh` |
|---|---|
| التحقق الأولي | يتحقق من Termux وملفات المصدر، ويرفض استبدال مشغّل غريب أو رابط رمزي موجود مكان `cronos` أو `cronos-yt`. |
| حزم النظام | يطلب `python` و`python-pip` و`python-setuptools` و`ffmpeg` و`nodejs` عبر `pkg install`. |
| اختيار مسار الاعتماديات | مع ملف صالح يستخدم `pip --require-hashes`؛ دون ملف صالح يحتاج إلى بيئة مثبتة سابقة. |
| النسخ الاحتياطي | يحفظ الإعدادات ولقطة SQLite متسقة، عند وجودهما، في مجلد النسخ الاحتياطية الخاص. |
| تجهيز البيئة | يبني بيئة مرشحة منفصلة أو ينسخ البيئة السابقة؛ يثبّت حزمة CRONOS المحلية دون حل اعتمادياتها من جديد. |
| فحص الاستيرادات | يتحقق من استيراد حزم التطبيق؛ إذا نجح يصل إلى تبديل البيئة. |
| حفظ البيئة السابقة | عند التبديل يعيد تسمية البيئة القديمة إلى اسم من نمط `venv.previous.<timestamp>-<pid>`. الاحتفاظ بها لا يعني وجود استرجاع آلي كامل عند كل خطأ. |
| التخزين والتشغيل | يطلب إذن التخزين، ويحاول إنشاء مجلدات الوسائط، وينشئ المشغّلين، ثم يشغّل `--check`. |
| الفتح التلقائي | يفتح الواجهة في جلسة طرفية تفاعلية، إلا عند ضبط `CRONOS_NO_LAUNCH=1`. |

لا ينقل المثبّت مجموعة الوسائط إلى اسم جديد، ولا يمحو السجل لمجرد الترقية. بعض مراحل النظام والتخزين قد تتغير قبل حدوث خطأ لاحق؛ لهذا يجب قراءة ناتج كل مرحلة.

<a name="launch"></a>
## 8. التشغيل والتحقق بعد تثبيت ناجح

```bash
cronos
```

يعمل الأمر من أي مجلد لأن المثبّت يضع المشغّل داخل `$PREFIX/bin`. لا تحتاج إلى تنشيط البيئة الافتراضية يدويًا. يبقى `cronos-yt` اسمًا متوافقًا يشغّل التطبيق نفسه.

| الأمر | الغرض |
|---|---|
| `cronos --version` | عرض إصدار CRONOS. |
| `cronos --help` | عرض الخيارات الفعلية، دون بدء تنزيل. |
| `cronos --check` | فحص FFmpeg وFFprobe وNode.js واستيراد yt-dlp/EJS. لا يثبت نجاح الاتصال بـYouTube. |
| `cronos --doctor` | فحص أوسع للإصدارات والإعدادات وقاعدة البيانات ومجلدات الإخراج. لا يصلح المشكلات تلقائيًا. |
| `cronos --ui-preview` | عرض لوحة الواجهة دون تنزيل وسائط؛ قد ينشئ قاعدة البيانات المحلية إن لم تكن موجودة. |
| `cronos --motion-preview` | معاينة مؤثرات الطرفية دون تنزيل. |
| `cronos --no-animation` | فتح جلسة دون مؤثرات حركة؛ لا يغيّر التفضيلات المحفوظة. |
| `CRONOS_NO_MOTION=1 cronos` | تعطيل الحركة عبر متغير بيئة لهذه الجلسة. |

بعض هذه الأوامر يستورد حزم التطبيق أولًا؛ فظهور `ModuleNotFoundError` يعني أن بيئة التشغيل نفسها تحتاج إلى معالجة، وقد يمنع حتى فتح المساعدة.

## 9. استخدام الواجهة

تظل أسماء القوائم داخل التطبيق بالإنجليزية حاليًا. يتغيّر طول الاسم بحسب عرض شاشة الهاتف.

| العنصر | وظيفته |
|---|---|
| **Quick Download** | المسار الأبسط: رابط واحد، فحص الصيغ، اختيار فيديو أو صوت، مراجعة ثم بدء العمل. |
| **Video / advanced** أو **Download video** | اختيار الجودة وتفضيل FPS وخيارات الفيديو. |
| **Music / advanced** أو **Download music** | اختيار صيغة الصوت ومعدل MP3 والبيانات الوصفية المتاحة. |
| **Playlists** أو **Playlist Studio** | اختيار عناصر قائمة تشغيل وتحديد عددها وتصفيتها. |
| **Multiple URLs** أو **Batch links** | معالجة أكثر من رابط. |
| **Queue** أو **Download queue** | عرض المهام المحفوظة وتشغيلها وتغيير حالتها وأولوياتها. |
| **Library** أو **Media library** | البحث في الوسائط المسجلة وتصدير قوائمها. |
| **Tools & settings** | السجل والإحصاءات وتفضيلات التنزيل والمظهر والتشخيص والنسخ الاحتياطي وتحديث المحرك والمساعدة. |
| **Exit CRONOS** | الخروج من الواجهة. |

للتنقل استخدم السهمين ↑ و↓ ثم Enter، أو مفاتيح التنقل المدعومة في القائمة. **Back** يرجع خطوة. يلغي Ctrl+C السؤال أو العملية الحالية بحسب موضعك.

لأول تنزيل: افتح **Quick Download**، ألصق رابط HTTPS لفيديو يحق لك حفظه، واختر النوع والجودة المتاحة، ثم راجع الاختيار وأكّد الإذن بالحفظ. قد يُعرض الإرسال إلى الطابور بدلًا من التنزيل الفوري. تأكيد إذن حفظ الوسائط خطوة داخل التطبيق، وليس تسجيل دخول إلى حساب YouTube.

<a name="downloads"></a>
## 10. أمثلة أوامر التنزيل

الأمثلة تستخدم `VIDEO_ID` و`PLAYLIST_ID` كقيم توضيحية؛ استبدلها بمعرّفات روابط حقيقية تملك حق حفظها. انقل الرابط كاملًا بين علامتي اقتباس؛ فالرابط الذي يحتوي على `&` قد يُفسَّر بصورة مختلفة في الطرفية إذا لم تقتبسه.

### فيديو بدقة مستهدفة 720p

```bash
cronos --url 'https://www.youtube.com/watch?v=VIDEO_ID' --mode video --quality 720 --fps 30 --yes
```

الدقة ومعدل الإطارات **تفضيلات ضمن الصيغ المتوفرة**، وليسا رفعًا اصطناعيًا للجودة. قد يختار البرنامج جودة أقل إذا لم تتوفر المطلوبة. اختيار 60 لا يحوّل فيديو 30 FPS إلى 60 حقيقيًا. يفضّل H.264 حيث يتوفر؛ قد تكون الدقات الأعلى VP9 أو AV1، وقد تحتاج إلى مشغّل يدعمها.

### أفضل جودة متاحة

```bash
cronos --url 'https://youtu.be/VIDEO_ID' --mode video --quality best --yes
```

### صوت MP3 أو M4A

```bash
cronos --url 'https://music.youtube.com/watch?v=VIDEO_ID' --mode music --format mp3 --bitrate 192 --yes
cronos --url 'https://youtu.be/VIDEO_ID' --mode music --format m4a --yes
```

صيغ الصوت المقبولة هي `mp3` و`m4a` و`opus` و`flac` و`wav`. معدلات MP3 هي 128 و192 و256 و320 kbps. تحويل مصدر مضغوط إلى 320 kbps أو FLAC/WAV لا يستعيد التفاصيل المفقودة من المصدر.

### مجلد إخراج مخصص

```bash
cronos --url 'https://youtu.be/VIDEO_ID' --mode video --quality 1080 --output "$HOME/storage/shared/Movies/CRONOS-Custom" --yes
```

### عدة روابط

```bash
cronos --url 'https://youtu.be/VIDEO_ID_1' --url 'https://youtu.be/VIDEO_ID_2' --mode music --format opus --yes
```

### اختيار عناصر قائمة تشغيل

```bash
cronos --url 'https://www.youtube.com/playlist?list=PLAYLIST_ID' --playlist --mode music --format mp3 --items '1-5,9' --limit 20 --yes
```

`--items` يستخدم ترتيب العناصر الأصلي. `--limit` يحدّ عدد العناصر التي يجري اكتشافها؛ العناصر خارج هذا الحد لن تصبح متاحة لمجرد ذكر أرقامها. يتطلب `--playlist` رابطًا واحدًا ونوعًا عبر `--mode`. يتطلب `--playlist-search` كذلك `--playlist`.

### ترجمات الفيديو عند توفرها

```bash
cronos --url 'https://youtu.be/VIDEO_ID' --mode video --quality 720 --subtitles manual --subtitle-languages 'ar,en' --yes
```

استبدل `manual` بـ`automatic` لطلب الترجمات الآلية. المخرجات ملفات ترجمة جانبية حيث يدعمها المصدر. لا يُنشئ التطبيق ترجمة عربية إذا لم يوفرها المصدر.

`--yes` يعني أنك تؤكد الإذن بحفظ الروابط المحددة في هذا الأمر. وهو ليس خيارًا لتجاهل جميع الأخطاء. عند استعماله تتوقف مفاتيح التحكم التفاعلية P/R/C الخاصة بالجلسة؛ استخدم الواجهة إذا أردت هذه المفاتيح. يحتاج العمل غير التفاعلي إلى `--yes`. وقد تتطلب الدفعات الكبيرة `--confirm-large-batch` بعد مراجعة عدد المهام؛ الحد الافتراضي 10.

<a name="queue"></a>
## 11. الطابور والإيقاف والاستئناف

### إضافة مهمة دون تنزيل فوري

```bash
cronos --url 'https://youtu.be/VIDEO_ID' --mode video --quality 720 --enqueue --yes
cronos --queue-list
```

### تشغيل المهام المنتظرة بعد مراجعتها

```bash
cronos --run-queue --yes --confirm-queued
```

المهام القادمة من جلسة سابقة تحتاج إلى تجديد الإذن. إذا تجاوز العدد حد الدفعة الكبيرة، راجعه ثم أضف `--confirm-large-batch` إلى أمر التشغيل. أمر تشغيل الطابور يتعامل مع حالة **queued**؛ أعد المهام المتوقفة أو الفاشلة إلى الانتظار من **Queue → Pause / resume jobs** قبل إعادة التشغيل.

### تغيير أولوية مهمة

```bash
cronos --queue-set-priority 12 9
```

استبدل 12 بمعرّف من `--queue-list`. المجال 0–9، والأعلى يُقدّم في ترتيب الانتظار. لا يُستخدم هذا الأمر لتغيير مهمة تعمل بالفعل.

### أثناء التنزيل التفاعلي

| المفتاح | السلوك |
|---|---|
| P | طلب الإيقاف المؤقت بعد الجزء الحالي؛ ليس توقفًا فوريًا مضمونًا لكل عملية خارجية. |
| R | استئناف العمل. |
| C | إلغاء التنزيلات النشطة مع إبقاء الأجزاء الجزئية حيث يدعمها المسار. |
| Ctrl+C | مقاطعة العملية الحالية. |

الطابور محفوظ على القرص، لكن CRONOS **ليس خدمة خلفية أو daemon يبدأ العمل تلقائيًا بعد إغلاق Termux**. إعادة المحاولة قد تستفيد من ملفات `.part` عند تكرار الرابط والصيغة والجودة والوجهة؛ لا توجد ضمانة للاستئناف مع كل مصدر أو مرحلة تحويل. لا تحذف الأجزاء إذا أردت محاولة الاستئناف.

<a name="settings"></a>
## 12. الإعدادات والمظهر

افتح **Tools & settings → Download preferences** لتغيير مجلدات الإخراج والصيغ والجودة والتوازي والترجمات. تُحفظ التغييرات محليًا.

| الإعداد | القيمة الافتراضية في 3.0.1 | المجال أو الملاحظة |
|---|---|---|
| التنزيلات المتوازية | 2 | من 1 إلى 4. |
| حد عناصر القائمة | 50 | من 1 إلى 500. |
| حد تأكيد الدفعة الكبيرة | 10 | من 1 إلى 500. |
| صيغة الصوت | MP3 | MP3 / M4A / OPUS / FLAC / WAV. |
| معدل MP3 | 192 kbps | 128 / 192 / 256 / 320. |
| دقة الفيديو | 1080p | من الدقات المدعومة، بحسب توفر المصدر. |
| تفضيل الإطارات | 60 | 30 أو 60؛ دون توليد إطارات جديدة. |
| سقف السرعة | 0 | غير محدود؛ يطبّق السقف على **كل تنزيل نشط** لا على المجموعة كلها. |
| أجزاء متزامنة لكل تنزيل | 2 | من 1 إلى 4. |
| الترجمات | none | none / manual / automatic؛ اللغة الافتراضية en. |

سقف السرعة بوحدة KiB/s؛ مثلًا 1024 يقارب 1 MiB/s لكل تنزيل. التوازي قد يرفع استهلاك الشبكة الإجمالي. إذا كانت الحزمة أو ذاكرة الجهاز محدودة، ابدأ بتوازٍ 1 وجودة متوسطة.

افتح **Tools & settings → Appearance & motion** لتعديل الثيم والحجم المضغوط والمقدمة والسرعة والأسلوب وتقليل الحركة. الأساليب المتاحة: `glide` و`pulse` و`typewriter`؛ السرعات: `calm` و`normal` و`swift`.

عند الوميض أو بطء الطرفية، استعمل `cronos --no-animation` أو فعّل تقليل الحركة من الإعدادات. تُعطّل الحركة تلقائيًا في بعض البيئات غير التفاعلية أو عند `TERM=dumb` أو `CI=1`.

<a name="files"></a>
## 13. أماكن الملفات والنسخ الاحتياطي

المسارات التالية هي الافتراضية؛ قد تختلف إذا عدّلت الوجهات أو متغيرات XDG.

| المحتوى | المسار |
|---|---|
| مصدر Git الموصى به | `~/CRONOS-Termux` |
| الفيديو | `/storage/emulated/0/Movies/CRONOS-YT` |
| الصوت | `/storage/emulated/0/Music/CRONOS-YT` |
| الإعدادات | `~/.config/cronos-yt/settings.json` |
| السجل والطابور وبيانات الإذن | `~/.local/share/cronos-yt/history.sqlite3` |
| Python المثبت للتطبيق | `~/.local/share/cronos-yt/venv/bin/python` |
| سجل الأخطاء الدوّار | `~/.local/state/cronos-yt/errors.log` |
| النسخ الاحتياطية | `~/.local/state/cronos-yt/backups` |

بقاء أسماء `CRONOS-YT` و`cronos-yt` داخليًا مقصود للتوافق مع التثبيت السابق. لا تغيّرها جماعيًا عند ترقية الاسم الظاهر إلى CRONOS.

### المكتبة والتصدير

```bash
cronos --library
cronos --library --library-search 'كلمة من العنوان' --library-kind video
cronos --stats
cronos --library-export "$HOME/storage/downloads/cronos-library.csv"
```

المكتبة تبحث في التنزيلات التي سجّلها CRONOS، وليست ماسحًا شاملًا لكل ملفات الهاتف. يمكن التصدير أيضًا إلى ملف ينتهي بـ`.m3u`. التصدير بالأوامر يرفض استبدال ملف موجود؛ اختر اسمًا جديدًا.

### النسخ الاحتياطي

```bash
cronos --backup
```

أرشيف النسخ الاحتياطي قد يتضمن سجلًا وروابط خاصة بك، وهو ليس أرشيف الوسائط وليس مشفّرًا. لا ترفعه إلى المستودع. **لا يوجد أمر عام لاستعادة الإعدادات وقاعدة البيانات تلقائيًا** في هذه النسخة؛ لا تستبدل قاعدة SQLite أثناء تشغيل التطبيق. أما `--restore-engine` فهو استرجاع لحزم المحرك فقط.

<a name="updates"></a>
## 14. تحديث الشيفرة وتحديث المحرك

| ما تريد تحديثه | الطريقة | ما لا يفعله |
|---|---|---|
| شيفرة CRONOS من المستودع | `git pull --ff-only` ثم `bash install.sh` | لا يضمن اكتمال اعتماديات نسخة مرشحة. |
| حزم المحرك وواجهة Python | `cronos --update` باستخدام ملف مقفل صالح | لا يجلب شيفرة CRONOS الجديدة من GitHub. |
| تطبيق Termux نفسه | من مصدر تثبيت Termux | لا ينشر تحديثات CRONOS. |
| حزم نظام Termux | إدارة `pkg` | إجراء منفصل قد يؤثر في بيئة Python والأدوات الأخرى. |

### تحديث استنساخ المصدر

1. أنهِ التنزيلات وأغلق الجلسات الأخرى، ثم خذ نسخة احتياطية إن كان التطبيق يعمل.
2. افحص المستودع قبل سحب التحديث:

```bash
git -C "$HOME/CRONOS-Termux" remote get-url origin
git -C "$HOME/CRONOS-Termux" status --short
```

3. إذا لم توجد تعديلات محلية غير محفوظة وكان origin صحيحًا، نفّذ:

```bash
git -C "$HOME/CRONOS-Termux" pull --ff-only origin main && CRONOS_NO_LAUNCH=1 bash "$HOME/CRONOS-Termux/install.sh" && cronos --version && cronos --check
```

استخدام `&&` يوقف السلسلة عند فشل خطوة. **حتى بعد فشل `--check` قد يكون المثبّت قد أتم تثبيت الشيفرة**؛ افحص الناتج ولا تفترض تراجعًا آليًا. اقرأ `CHANGELOG.md` قبل تشغيل تنزيل جديد.

إذا رفض Git بسبب تعديلات محلية أو اختلاف الفروع، توقف واحفظ عملك قبل حل الاختلاف. لا تستعمل `reset --hard` أو الحذف لتجاوز الرسالة.

### تحديث المحرك المقفل

ملف الاعتماديات الحالي غير مكتمل، لذلك التوقف هنا متوقع. بعد نشر ملف صالح ومراجع:

```bash
CRONOS_LOCK_FILE="$HOME/CRONOS-Termux/requirements.lock" cronos --update
```

تحديد `CRONOS_LOCK_FILE` مهم عند العمل من مسار Git المقترح: الاختيار الافتراضي يفحص `~/CRONOS/requirements.lock` إن كان موجودًا، ثم الملف المضمّن في حزمة التطبيق. وجود ملف قديم في `~/CRONOS` قد يفسر اختيار ملف مختلف.

يوجد `cronos --update-unpinned --yes` كخيار صريح لتثبيت حزم لم تُقفل إصداراتها وبصماتها مسبقًا في المشروع؛ لا يُقدَّم هنا كإصلاح افتراضي أو بديل مكافئ لملف البصمات. قد يتصل بمصدر الحزم ويثبت إصدارات جديدة.

### استرجاع المحرك

```bash
cronos --restore-engine
```

يعتمد الاسترجاع على لقطة حزم وعجلات rollback محفوظة ومتحقق من بصماتها. قد يفشل إذا لم توجد النسخة المطلوبة أو لم تكتمل الذاكرة المحلية. لا يسترجع شيفرة CRONOS السابقة ولا الإعدادات ولا الوسائط.

<a name="share"></a>
## 15. المشاركة من تطبيقات أندرويد

بعد نجاح تثبيت التطبيق:

```bash
cronos --install-share-handler
```

ينشئ هذا `~/bin/termux-url-opener` إذا لم يكن موجودًا؛ لا يستبدل معالج مشاركة سابقًا. بعدها جرّب **مشاركة رابط → Termux** من YouTube أو المتصفح. يفتح CRONOS لطلب الخيارات والإذن بدل بدء تنزيل بلا مراجعة. إتاحة عنصر Termux في المشاركة تعتمد أيضًا على التطبيق ونوع المحتوى المشارك.

Termux:API ليس شرطًا لتنزيل رابط تلصقه يدويًا. لو رغبت في وظائفه الاختيارية، ثبّت تطبيق Termux:API المتوافق من مصدر Termux نفسه، ثم:

```bash
pkg install termux-api
```

يمكن أن يساعد `termux-media-scan` في تحديث معرض الوسائط؛ وجود أداة الأمر وحدها دون التطبيق المرافق والأذونات لا يضمن عملها.

<a name="troubleshooting"></a>
## 16. حل الأخطاء

| الرسالة أو المشكلة | التفسير والخطوة المناسبة |
|---|---|
| `reviewed SHA-256 requirements.lock unavailable for fresh installation` | ملف الاعتماديات غير مكتمل ولا توجد بيئة مثبتة يمكن إعادة استخدامها. راجع حالة الإصدار؛ لا يتسبب إعادة الاستنساخ وحده في إكمال الملف. |
| `Refusing unreviewed index resolution` | أداة المشرف تتطلب قرارًا صريحًا عبر `CRONOS_TRUST_INDEX=1` بعد مراجعة المتطلبات. ليست خطوة تثبيت تلقائي للمستخدم النهائي. |
| `cronos: command not found` | الاستنساخ وحده لا ينشئ المشغّل. افحص نجاح المثبّت، ثم `command -v cronos`. إذا كان المشغّل موجودًا، افتح جلسة Termux جديدة. |
| `This installer must run inside the Android Termux app` | يُشغّل المثبّت خارج Termux أو في بيئة لا تحمل PREFIX المتوقّع؛ شغّله في تطبيق Termux الأصلي. |
| `Unrelated launcher ... left unchanged` أو `Symlink ... left unchanged` | يوجد مشغّل أو رابط غير مملوك للمثبّت. افحصه وحدد مصدره قبل نقله؛ لا تحذفه آليًا. |
| `ModuleNotFoundError` | حزم Python المطلوبة غير متاحة في البيئة التي شغّلت التطبيق. اختبر Python الخاص بالتطبيق؛ لا تعتمد على `python` العام وحده. |
| `No module named ...` بعد تشغيل `python -m cronos_yt` | قد تكون تستخدم Python النظام بدل بيئة التطبيق. استعمل `cronos` أو مسار Python الموثق. |
| Node.js قديم | افحص `node --version`؛ فاحص CRONOS يتطلب 22+. عالج حزمة nodejs عبر مستودع Termux المتوافق مع جهازك، ثم أعد `cronos --check`. |
| `Permission denied` عند حفظ الوسائط | أعد `termux-setup-storage`، وافحص إذن أندرويد والوجهات عبر `cronos --doctor`. |
| تشغيل `./install.sh` يفشل | استخدم `bash install.sh` من المصدر داخل مساحة Termux الخاصة؛ لا حاجة إلى تغيير إذن التنفيذ لمجرد هذا الأسلوب. |
| `No such file or directory` | افحص `pwd` و`ls` واسم ZIP ومجلده الداخلي؛ مسارات ZIP وGit مختلفة. |
| `destination path ... already exists` | لا تحذف المجلد. افحص إن كان استنساخ المشروع الصحيح واستعمل مسار التحديث أو مجلدًا جديدًا. |
| فشل فهرس حزم Termux | افحص الاتصال والوقت ورسائل `pkg update`. راجع دليل إدارة حزم Termux؛ لا تعطل التحقق من TLS لتجاوز خطأ. |
| لا تظهر حركة المقدمة | تحقق من إعدادات المظهر و`CRONOS_NO_MOTION` وكون الجلسة تفاعلية؛ غياب الحركة لا يعني فشل التنزيل. |
| الجودة المطلوبة غير متوفرة | CRONOS يختار من صيغ المصدر ولا يرفع الدقة أو يولّد FPS إضافيًا. |
| الفيديو صامت أو بانتظار الدمج | افحص FFmpeg والاعتماديات؛ بعض الصيغ تصل كصوت وفيديو منفصلين قبل الدمج. لا تنقل الملف المؤقت أثناء العمل. |
| الملف موجود ولا يظهر في المعرض | افحص مسار Movies/Music الفعلي، ثم جرّب إعادة فحص الوسائط مع Termux:API إن كان مثبتًا. |
| اختفت مهمة الطابور من التشغيل | افحص حالتها؛ `--run-queue` يشغّل المنتظر فقط، والمهام القديمة تحتاج تجديد الإذن. |
| أغلق أندرويد Termux أو أوقف التنزيل | افتح التطبيق مجددًا وافحص الطابور والأجزاء الجزئية. السماح بتشغيل Termux في الخلفية قد يساعد، لكنه ليس ضمانًا ضد قيود النظام. |
| خطأ استخراج من YouTube | افحص الرابط والاتصال والتشخيص وحالة إصدار المحرك؛ لا تعد تحديثًا مقفلًا ناجحًا بينما ملف الاعتماديات ناقص. المحتوى الخاص أو المقيد لا يُتجاوز بهذه الأداة. |

عند طلب المساعدة أرسل إصدار CRONOS وPython وNode ورسالة الخطأ بعد مراجعتها. لا تنشر قاعدة بياناتك أو سجل المشاهدة أو روابط خاصة أو أرشيف النسخ الاحتياطية.

<a name="verification"></a>
## 17. التحقق على الهاتف

من مجلد المصدر المطابق للإصدار المثبت:

```bash
cd "$HOME/CRONOS-Termux"
bash verify_termux.sh
```

إذا استخدمت ZIP، استبدل المسار بمجلد المصدر الفعلي. يشغّل السكربت Python الخاص بالتطبيق لفحص الاستيرادات والاختبارات المحلية ومعاينة الواجهة وفاحص الاعتماديات وتجميع المصدر. قد تُنشأ ملفات كاش Python محلية، ولا ينزّل وسائط.

يمكن تشغيل مجموعة الاختبارات صراحةً بالبيئة الصحيحة:

```bash
"$HOME/.local/share/cronos-yt/venv/bin/python" -m unittest discover -s tests -v
```

اختبارات التكامل اختيارية وتتطلب حزمًا حقيقية مثبتة، لكنها تحاكي استخراج المعلومات وتمنع الشبكة في الاختبار:

```bash
CRONOS_INTEGRATION=1 "$HOME/.local/share/cronos-yt/venv/bin/python" -m unittest discover -s tests/integration -v
```

نجاح الفحص المحلي لا يثبت تنزيلًا حيًا من YouTube. افحص يدويًا المقدمة والقوائم وحفظ الإعدادات وظهور المكتبة والطابور، ثم جرّب وسائط يحق لك حفظها. يجب تسجيل الجهاز وإصدار Python ونتيجة الاختبارات عند إعلان دعم فعلي.

<a name="maintainer"></a>
## 18. إكمال ملف الاعتماديات — للمشرف

هذا القسم عمل صيانة يحتاج إلى شبكة ومراجعة واختبار، ولا يعني أن الإصدار الحالي اجتازه. لا تنفّذ سلسلة تنتهي بالتثبيت دون فحص ما أنتجته.

1. راجع `requirements.in` ومتطلبات Python وإصدارات حزم Termux.
2. على بيئة Termux مناسبة، جهّز أدوات Python المطلوبة، ثم ولّد ملفًا مرشحًا:

```bash
pkg install python python-pip python-setuptools
cd "$HOME/CRONOS-Termux"
CRONOS_TRUST_INDEX=1 bash scripts/generate_lock.sh
```

الأداة تنشئ بيئة مؤقتة، وتثبّت pip-tools، وتحلّ الحزم عبر الفهرس المكوّن، وتولّد إصدارات وبصمات. فحصها يتحقق من بنية الملف، ولا يثبت وحده سلامة الناشر أو خلو الحزم من الثغرات.

3. راجع الإصدارات والمصادر والبصمات والتوافق مع بنية أندرويد المستهدفة، ثم وحّد الملفين حتى لا تحمل حزمة التطبيق نسخة مختلفة:

```bash
cp requirements.lock cronos_yt/requirements.lock
```

4. وفّر أدوات `pip-audit` وRuff أو pyflakes والاعتماديات الحقيقية في بيئة التحقق، ثم شغّل:

```bash
bash scripts/ci_check.sh
```

فشل البوابة عند غياب أدوات التدقيق أو ملف مقفل صالح متوقع؛ لا تسجّل الفحص ناجحًا عند تجاوزه. تحقّق على Python 3.12 و3.13 وبنى Termux المستهدفة، ثم اختبر التثبيت والترقية والاسترجاع على الهاتف. يحتاج بعض الاعتماديات ذات الأجزاء الأصلية إلى معالجة خاصة بأندرويد.

يوجد المسار الاختياري:

```bash
CRONOS_SYSTEM_SITE=1 CRONOS_NO_LAUNCH=1 bash install.sh
```

يسمح هذا بمشاركة حزم Python الأصلية التي يثبتها Termux، ومنها Brotli وPyCryptodome. لا يزيل الحاجة إلى ملف اعتماديات صالح ومطابق؛ وقد لا يحل جميع تعارضات الحزم. وثّق هذه البيئة صراحةً إذا استُخدمت.

5. لا تغيّر حالة README إلى «إصدار مستقر» إلا بعد اكتمال هذه الفحوص ونشر نتائجها. سجّل القيود التي بقيت دون تحقق في `CHANGELOG.md` و`SECURITY.md`.
